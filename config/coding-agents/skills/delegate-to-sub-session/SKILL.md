# サブセッションへサブタスクを引き継ぐ

メインのセッションのコンテキストを汚さずに、サブタスクを切り分けたいときに使う手順。

## サブエージェントとの使い分け

サブエージェントとの違いは、**引き継ぎ先が対話型セッションで、確認プロンプトに人が答えられる**点。

|                                                   | 引き継ぎ先                   |
| ------------------------------------------------- | ---------------------------- |
| 調査・読み取り中心で、結果だけ欲しい              | サブエージェント（Agent）    |
| 実行の承認を人に挟みたい（例: `terraform apply`） | サブセッション（このスキル） |
| 途中経過を人が見て、随時介入する必要がある        | サブセッション（このスキル） |

## 引き継ぎの手順

引き継ぎ先は**タスクごとに新しく作る**。

1. `ListAgents` で**自分のセッション名**を確認する。
   出力の1行目に`This session is <名前>` として出る。
   引き継ぎメッセージの `<引き継ぎ元のセッション名>` に埋める。
2. herdr 配下かどうかを判定する。`echo $HERDR_ENV` が `1` なら配下。
3. 配下なら、ペインを分割してその場でサブセッションを起動する
   （「herdr でペインを分割して起動する」を参照）。
   配下でなければ、ユーザーに新しいターミナルで `claude` を起動してもらう。
   起動したらフォーカスはそのペインに移る。
4. 完了報告が届いたら、ペインを閉じる。

### herdr でペインを分割して起動する

引き継ぎ内容は `claude` の引数として渡す。

内容はクォートを含む複数行なので、シェルに直接書かず、スクラッチパッドのファイル経由で渡す。

```bash
cat > <スクラッチパッド>/handoff.txt <<'EOF'
<引き継ぎ内容>
EOF
herdr agent start <ラベル> --cwd "$PWD" --split right --focus -- claude "$(cat <スクラッチパッド>/handoff.txt)"
```

- `<ラベル>` は herdr のペイン用の名前。タスクが分かる短い名前にする。
- 終わったペインは `herdr pane close <pane_id>` で閉じる。
  `pane_id` は起動時の出力に入っている。

### 手動でターミナルを起動してもらう場合

ユーザーの操作は `claude` の起動まで。そのあとはメインセッション側で `ListAgents` で宛先名を確認し、`SendMessage` で送る。

- **起動直後は一覧に出るまで数秒かかることがある**。
- 宛先は `ListAgents` の表示をそのままコピーする。`[ref]` は同名が複数あるときだけ付ける。
- 引き継ぎ先が `ListAgents` から消えていたら、そのセッションは終了している。メッセージは届いていない。

## 引き継ぎメッセージのテンプレート

起動時の引数でも `SendMessage` でも、内容は同じ。
`SendMessage` の場合は先頭行だけがプレビューに出るので、**1行目は単体で意味の通る要約**にする。

```text
引き継ぎ: <何をするか（1文）>

## 背景
<なぜこれをやるか、関連する issue やタスクの場所、現在の状態>
<確認済みの事実（例: バケットは未作成であることを aws s3 ls で確認済み）>

## やること
<実行するコマンドを順に、コードブロックで>
<判断が要る箇所と、その判断基準>

## やらないこと
<後続タスク、触ってほしくないファイル>

終わったと判断したら、まずユーザーに結果を示して完了の確認を取ってください。
承認が得られてから、結果を SendMessage で <引き継ぎ元のセッション名> 宛に報告してください。
自己判断で報告しないでください。
```

## ルール

- **完了判定は人に委ねる**。
  ユーザーの承認を経てから報告させる。
- **やらないことを必ず書く**。
  引き継ぎ先は全体像を知らないため、書かないと後続タスクまで進めてしまう。
- 背景には「すでに確認済みの事実」を書く。引き継ぎ先が同じ調査をやり直さずに済む。
