# memos リポジトリにメモを追加する

- `memos/` : 技術トピック別のメモ本体（このスキルの主な追加先）。
- `_global/` / `_repo/` / `_local/` : コミットされない作業用ディレクトリ。
  3スコープの定義は config/coding-agents/AGENTS.md の「一時ディレクトリは共有範囲で3つに分かれる」節に従う。

書き込み先を決めるルール:

- 残す価値のある技術メモなら `memos/`。
- そうでなければ作業用ディレクトリへ。共有範囲で `_global/` / `_repo/` / `_local/` を選ぶ。
- 迷ったらユーザーに確認する。

`_global/` / `_repo/` / `_local/` はコミットされないので、**残したい知見をここに書かない**。

## 手順

1. 書く場所の worktree を確認する。
   `git rev-parse --git-dir` と `git rev-parse --git-common-dir` が同じ場所を指すかどうかで判定する。
   - 同じなら、いまはメイン worktree にいる。
     extract-to-worktree スキルで新しい worktree に切り出し、その中でメモを書く。
   - 違うなら、すでにリンクされた別の worktree にいる。
     切り出さず、そのまま書く。
   extract-to-worktree が起動した Claude が add-memo をまた実行しても、切り出しを繰り返さないための歯止めである。
2. 追加先を決める。
   - まず `ls memos/` と `grep -ril <キーワード> memos/` で**既存の該当メモを探す**。
   - 既存メモがあれば新規作成せず、そこに追記する（適切なセクション）。
   - トピックがディレクトリ（例: `memos/git/`, `memos/typescript/`）なら、その中の
     適切なファイルに追記するか、新しい `<topic>.md` を作る。
   - 該当がなければ `memos/<topic>.md` を新規作成する。ファイル名は小文字ケバブケース。
3. 書き出す前に、次の 2 点をユーザーに確認する。
   - **何を書くか**: 会話のどの部分を残すか（要点を箇条書きで示す）。
   - **どこに書くか**: 手順 1 で決めたファイルパス。新規作成か既存への追記かも示す。
   ユーザーが「おまかせ」などと言った場合はそのまま進めてよい。
4. 内容を書く。既存メモの書き方に合わせる（下記ルール参照）。
5. `pnpm markdownlint`（または `npx markdownlint-cli2 '<追加したファイル>'`）で lint を通す。
6. コミットは行わない。

## 書き方のルール

- 見出しは H1 がファイルタイトル 1 つだけ。以下は H2 → H3 と順に下げる。
- 日本語の地の文。技術用語・コマンドは原語のまま。冗長な説明はせず要点だけ書く。
- 参考 URL は `<https://example.com>` の形式（山括弧で囲む）で書く。
  節ごとにまとめる場合は `### 参考` の下に置く。

## やらないこと

- メイン worktree には書かない。
- ユーザーが言っていない内容を推測で膨らませない。書くのは実際に得られた知見だけ。
- 既存メモの体裁の一括修正など、依頼されていない変更をしない。
